## Important
- ☑ CORRIGÉ (`E2E_SKIP_BUILD=1 npx playwright test` sous Git Bash, échec explicite si `.output/server/index.mjs` absent ; vérifié : 409 s en complet, 14 s en skip) — `playwright.config.ts:30` (`webServer.command`) — `npm run build` est relancé à chaque `npm run test:e2e` (environ 7 min), car le serveur est arrêté en fin de run et `reuseExistingServer` ne sert donc à rien entre deux runs. Acceptable pour une QA finale, pénible en boucle. Correction simple et sans risque : rendre le build optionnel, par exemple `process.env.E2E_SKIP_BUILD ? 'npx nuxt preview --port 3100' : 'npm run build && npx nuxt preview --port 3100'`, à documenter en T14 avec l'avertissement « build possiblement périmé ». Alternative sans code : lancer soi-même `npx nuxt preview --port 3100` (hors CI, il est réutilisé). À noter aussi : `npm run build` écrase `.nuxt/` et `.output/`, ce qui peut perturber un `nuxt dev` en cours.
- ☑ (corrigé : exit 2 si écart entre « error TS » brut et analysé) `scripts/typecheck-baseline.mjs:49` — le garde-fou d'outillage ne se déclenche que si `status !== 0 && total === 0`. Si `nuxi typecheck` plante en cours de route après avoir affiché quelques erreurs, ou si des erreurs globales sans fichier (`error TS5023: …`, tsconfig cassé) coexistent avec des erreurs de fichier, elles sont ignorées sans bruit : le script peut conclure « 0 nouvelle » à tort. Correction : compter aussi les occurrences de `error TS\d+` dans la sortie et sortir en code 2 si ce nombre dépasse `total` (lignes non reconnues par `lineRe`).
- ☑ (corrigé par l'orchestrateur : baseline expliquée, `typecheck:baseline` interdit sans accord) `.claude/agents/qa.md:27` — décrit `npm run typecheck` comme `nuxi typecheck` alors que c'est maintenant le wrapper baseline. Rien n'interdit à un agent de lancer `npm run typecheck:baseline` pour faire disparaître une régression. Ajouter une phrase : ne jamais régénérer la baseline sans validation de l'utilisateur, et `typecheck:strict` donne la liste complète.
